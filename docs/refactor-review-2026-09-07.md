# 2026-09-07：模型格式恢复与维护性重构

本轮处理博客文章无法显示译文的问题，并审查内容脚本、后台、共享核心、Provider runtime、Options、Popup、构建和测试基础设施。所有验证使用 Node、happy-dom、静态检查和构建检查，没有启动浏览器，也没有调用真实付费模型 API。

## 故障证据与修复

用户截图中的错误是“模型返回的 JSON 无法解析”。对[故障文章](https://bcantrill.dtrace.org/2026/09/05/the-revolt-of-the-reader/)获取原始 HTML/CSS 后，现有 DOM 测试环境能扫描并渲染标题及 14 个正文段落，共 15 块；未发现需要特定域名适配的扫描问题。

确认的代码缺陷是：模型以 `finishReason="stop"` 结束时，格式/数量/ID 校验错误直接终止批次，而旧恢复逻辑只处理 `finishReason="length"`。同时 `model.response.validated` 在解析前就被记录，给排障带来误导。

修复遵守以下约束：

- JSON、译文数量和 ID 仍严格校验，统一协议错误码为 `MODEL_RESPONSE_INVALID`。
- 格式错误与输出截断共用每个原始批次两次二分预算；多段按字符均衡拆批，单段可拆文本。最多产生五个模型请求组，每组仍受最多三次网络尝试限制。
- 原文只作为不可信数据进入翻译 prompt，不修补损坏 JSON，不猜测段落 ID，不缓存非法输出。
- 恢复成功按原始顺序合并译文；失败或取消仍保留所有已经发生的调用和用量。
- 只有校验成功才发出 `model.response.validated`；格式异常发出 `model.response.invalid`，调试事件不保存模型响应正文。

新增五个恢复测试在修复前全部失败，首例精确复现截图错误；修复后全部通过。整链集成测试连接真实内容脚本、后台消息路由及翻译器，仅替换外部 Provider：首次返回非法 JSON 后，15 块全部显示译文，原文和链接不变，元数据过滤和用量累计正确。

仓库中的博客 fixture 保留网页结构和长文、引号、内联链接等特征，使用原创测试正文。原始页面抓取仅用于本次诊断，没有把整篇文章复制进仓库。没有取得用户当时的 Provider 原始响应，因此不能断言具体是哪一处引号、截断或模型输出导致最初的解析失败。

## 重构结果

| 范围 | 原维护问题 | 当前职责划分 |
| --- | --- | --- |
| 模型翻译 | prompt、重试、超时、用量和递归恢复混在同一文件 | `model-request` 构造请求；`model-client` 执行网络；`model-usage` 聚合用量；`model-translator` 编排；`model-translation-recovery` 只处理拆分 |
| 后台消息与设置 | 网页生命周期与设置操作混合，多条保存路径重复串行读改写 | `run-message-handlers` 承担网页任务，router 保留来源检查和路由；设置共用串行写入入口 |
| 内容脚本 | mutation 文本、节点配对混合，加载清理和记录有效性判断重复 | 独立 `replacement-node-pairing`；监听器明确移除、新增、统一失效顺序；加载状态复用小型判断与清理函数 |
| Popup | 消息状态与 DOM 操作交错 | `popup-app` 编排动作，`popup-view` 管理文案、控件和事件绑定 |
| Options / Core | 语言冲突规则重复，配置授权和保存流程与 Vue 状态混合 | 共用 `core/language-selection`；`providerSetup` 隔离授权、保存及连接测试 |
| 构建 | 三套参数/产物比较逻辑，Vue 编译器混在入口中 | 共用 `build-outputs`，独立 `vue-sfc-plugin`，保留真实读取异常；`--check` 不写文件 |
| 测试 | 无截止时间等待、陈旧 DOM 假设、DOM 身份断言失败会格式化庞大对象 | 共用有界 `waitFor`，核对当前 carrier 契约，使用布尔身份断言及中文失败原因 |

未为满足行数机械拆分已经清楚的 SDK 适配器、纯函数、样式与 Vue 模板。`TranslationRun` 的依赖接线继续集中，方便看清一次运行的完整生命周期。

## 基线检查暴露的相邻问题

基线 `npm test` 为 284 通过、3 失败。一个 unit mock 仍提供旧 scanner 接口；两组 X 测试中的 DOM 对象断言导致失败格式化耗尽进程内存。修正断言后进一步暴露了真实的短暂脱离问题：generated carrier 从 DOM 暂时移除时，恢复器提前清理 source，绕过了既有 mutation 防抖窗口。

恢复器现在先排队，在既有扫描前复核窗口处理永久移除，短暂重挂可继续使用同一真实译文节点；停止运行仍立即释放 tracked source。没有添加另一套定时器或跨来源的同文迁移。详见 [X 呈现复盘](./x-hover-rendering-postmortem.md)。

另外修复了已取消 signal 进入退避等待时未立即拒绝的问题，以及 Vue 编译器存在 scoped 样式时未绑定组件 scope ID 的缺口；均有独立回归。当前 Vue 组件没有 scoped style，所以该编译器修复不改变当前 UI 的构建结果。

## 评分规则

评分是代码审查的工程判断，用于记录扣分项和复评，不是自动度量或无缺陷保证。每个范围使用同一权重：

| 维度 | 权重 | 检查内容 |
| --- | --- | --- |
| 可读性 | 30% | 名字是否直接表达意图，主流程是否可直读，是否依赖隐含状态 |
| 职责与依赖 | 25% | 单一职责、依赖方向、重复规则、提取后是否增加无益跳转 |
| 异常与状态 | 25% | 异常优先、取消、竞态、恢复上限与状态清理 |
| 测试与文档 | 20% | 关键行为可复现、测试失败可定位、产物检查、代码地图与诊断语义一致 |

判定门槛是每个审查范围均达到 9.5，不能靠其他范围的高分抵消低分。低于门槛时继续解决具体扣分项，再做交叉复审。分项与本次证据见下表；各范围等权汇总仅用于概览。

| 范围 | 初评 | 复评 | 仍保留的复杂性 |
| --- | ---: | ---: | --- |
| 内容脚本 | 8.80 | 9.52 | DOM 替换、短暂脱离和动态状态本身需要多阶段处理 |
| 后台 / Provider | 9.17 | 9.56 | Chrome 持久化与取消竞态不可简单合并；响应事件不猜测 requestId |
| 共享核心 | 9.50 | 9.66 | 保留严格的不同边界校验，避免过度宽容 |
| Options | 8.90 | 9.56 | Vue 调试视图模板较长，Port 生命周期主要由完整页面 fixture 验证 |
| Popup | 8.90 | 9.61 | 协议不一致、超时和重载需要明确的状态分支 |
| 构建与测试基础设施 | 8.30 | 9.60 | Vue 编译支持面必须保留各类可诊断错误 |

综合复评约 **9.58/10**（按未四舍五入的加权分汇总），最低范围 **9.52/10**。模型持续返回非法内容时仍会有界失败；本轮没有通过改宽校验或无限调用来隐藏服务故障。
